# Nav Sylph

一个极简的个人导航与书签管理页面，部署在自己的服务器或电脑上，作为浏览器首页使用。

## ✨ 核心功能

| 功能 | 说明 |
|------|------|
| **自定义导航** | 首页的分类与链接自由增删改，直接在首页拖拽排版，改完一次保存 |
| **口令云端空间** | 无需账号：自设一条口令建空间，其他设备用同一口令连上同一份导航 |
| **超级搜索框** | 一个输入框兼顾搜索、检索书签与分享文本三件事 |
| **书签集中管理** | 导入浏览器书签，分类整理、快速检索、批量隐私与删除 |
| **WebDAV 远程备份** | 配置、书签与模块设置备份到 WebDAV，支持自动同步与按类型恢复 |
| **自定义模块** | 管理员按需启用服务器监控、备忘录、时间线等私人模块，并把公开模块开放给访客 |
| **安全特性** | bcrypt 密码、登录限流、HttpOnly 会话、设备与归属地校验 |

## 🧩 功能说明

设置集中在管理面板（页面底部文字栏的「管理」按钮），分为四个分区：**首页导航**（主题模式、默认搜索引擎、隐私模式、搜索引擎）、**收藏夹**（导入导出与收藏管理器）、**模块**（模块开关、监控目标与订阅来源、公开模块的开放开关）、**账户与备份**（登录安全、远程备份、退出登录）。首页导航的排版不在面板里，直接在首页编辑，见下。访客自己的模块开关与偏好也不在管理面板里，在首页编辑态的「导航设置」里，见「自定义模块」。

### 普通访问者的本地导航

无需登录即可在根首页点击底栏的「编辑」，调整导航分类、链接及排序。分类与链接确认后的有效操作立即保存到浏览器 IndexedDB。进入编辑后，「编辑」换成「取消」和「保存配置」，导航网格下方展开「导航设置」：可选默认搜索引擎、主题与是否显示导航图标；「管理搜索引擎」展开后可新增、编辑、排序和删除引擎，搜索地址沿用关键词前缀格式，当前默认那一条在名称右侧标出。「保存配置」后设置生效并收起编辑态，点「取消」只丢弃尚未保存的设置，已经保存的分类与链接操作保留。删除当前引擎后使用剩余第一项，最后一项不可删除。

页面底部的文字栏是「说明 / 同步 / 编辑（编辑态为 取消 与 保存配置）/ 管理」，管理员多一项「外观」用于快速切换主题。它只是页面操作入口，不承载设置内容。

编辑区域的「数据管理」集中提供撤销、导入导出及重置。「撤销上一操作」恢复上一次已保存配置。可通过「导出导航」保留 JSON 副本，通过「导入导航」校验并替换当前配置；「重置为当前默认」在取得最新已发布模板并确认后替换本机导航。其他标签页发生冲突时，先导出当前草稿，再决定是否采用另一标签页版本。

管理员发布新模板不会覆盖已有本地导航。普通配置与管理员个人首页独立，管理员身份确认后再切换；未完成的本地表单先由用户处理。普通导航不读取收藏库或私人模块。多设备共用同一份导航见下节的「口令云端空间」。刷新、浏览器重启、离线回访及静态资源升级保留本地副本；首次离线且没有副本时需联网重试。

清除站点数据、浏览器回收存储或结束隐私浏览可能删除本地导航，请定期导出备份。出现「未能保存到本机」时，当前改动尚未持久保存，应导出保留；不要将提示视为保存成功。

### 口令云端空间（跨设备同步）

不想登录、又要在几台设备上用同一份导航时，用**口令**：点底部文字栏的「同步」，自设一条 6 到 128 个字符的口令（区分大小写，首尾空格也算数），再输一次确认。检查后会告诉你这个口令有没有对应的空间：

- **还没有空间**：填入管理员发放的**一次性邀请码**（48 小时内有效、可撤销），确认后把当前本机配置上传，建出这个空间。
- **已有空间**：显示它的最近更新时间与条目数，由你选「使用云端配置」还是「以本机配置替换云端」。两个方向都会先把被替换的那一份留在本机，之后可以从同一个对话框里导出。

其他设备用同一口令连一次即可；此后**刷新会自动复用那台设备的连接凭据**，不必重新输口令，同一口令下的设备数量也没有上限。邀请码由管理员在后台 **首页导航** 分区的「同步空间邀请码」里生成——一次一张，只显示一次，用过、撤销或过期的那几张会淡出留作记录。

需要注意：

- 口令就是凭据：知道口令的人都能读写这个空间，遗失无法找回。本机只保存这台设备的连接凭据，**不保存口令本身**。
- 访问方式需要 HTTPS 或 localhost——口令在浏览器里派生，浏览器只在安全上下文提供该能力；用纯 `http://` 的局域网地址打开时，「同步」会明确提示不可用。
- 同步的范围是导航、个人搜索引擎，以及**公开模块**的启用与布局；收藏、私人模块和管理员设置不在其中。
- 日常改动会**自动同步**：停手半秒传一次，一直改也最多两秒传一次；打开页面、切回这个标签页或恢复网络时立刻检查一次，页面开着时每 30 秒检查一次（切走就暂停）。断网期间的改动留在本机，恢复后自动补传；失败会逐步拉长重试间隔，最长 5 分钟。
- 同一口令下的多台设备**同时改同一份配置**时，两边都会停下并各留一份：打开「同步」选择「采用云端（覆盖本机）」或「保留本机（覆盖云端）」，选之前可以先「导出两边」把两份都存下。不会逐字段自动合并。
- **停止同步**：打开「同步」→「停止同步」，确认后本机导航原样保留，只是不再与云端同步。云端空间与其他设备不受影响。已经到达服务端的那一次上传可能已经完成——停止不会撤回它。
- **换设备/凭据泄露**：打开「同步」→「撤销全部旧设备并重新连接」，重新输入口令确认。其他设备会立刻停止同步（各自保留本机导航、不会偷偷重建），本机换用新凭据继续，云端内容与版本号都不动。
- **容量**：每个空间最多 1 MiB 内容（导航 + 模块偏好之和），全站默认最多 1000 个空间、有效配置合计 1 GiB。写满时上传会被拒绝并提示精简，**已有内容与未上传的修改都不会丢**；管理员可以调小额度做测试。
- **管理员可以**：查看空间列表（只有内部标识、体积、版本与状态，看不到内容与凭据）、停用/删除某个空间、暂停新建、暂停全部同步。空间被停用或全局暂停时，设备保留连接、自动同步暂停（全局暂停每 5 分钟自查一次，恢复后自动继续）；界面会明确说是哪一种，不需要重新输口令。
- **删除云端空间**：打开「同步」→「删除云端空间」，需要**重新输入口令**确认。删除后云端配置消失，这台设备与其他所有已连接的设备都会立刻失效（各自回到「仅保存在本机」，导航都还在）；**这一步无法撤销**。删除后若想再用同一口令同步，需要用新的邀请码重新创建一个空空间——旧内容不会回来。删除要求在线：离线时无法确认删除结果，界面会直接拒绝。

### 管理员个人导航

登录后，首页的分类与链接属于管理员个人导航，可直接在首页上编辑。个人保存不会改变访客取得的站点默认首页。

管理员在其他设备正常登录后即可取得同一份个人导航、搜索引擎和模块配置，无需另设同步口令。页面打开、恢复可见或联网时检查服务器配置，可见期间每30秒检查一次。未保存草稿保留在当前页面，发生版本冲突时可继续编辑或取消后读取服务器版本。

退出当前设备后恢复该浏览器原有的普通本地导航，其他设备会话继续有效。保存结果尚未确认时，需先重试或刷新协调后退出。会话失效会隐藏私人内容；有草稿时可重新登录恢复，或明确放弃后继续使用普通导航。关闭页面会丢失未提交的管理员草稿。

- **进入编辑**：登录后点页面右下角的 **编辑** 按钮，首页进入编辑状态
- **调整分类**：拖动分类头的 ⠿ 改变顺序，✎ 重命名，✕ 删除
- **调整链接**：点击书签卡修改标题与 URL，卡上的 ✕ 删除该书签；每个分类末尾的「＋」新增链接，网格末尾的「＋ 添加分类」新建分类
- **保存**：编辑期间的改动只保留在本地，点 **保存编辑** 一次性提交；按 `Esc` 可确认放弃本次草稿；会话失效时隐藏私人内容并提供重新登录恢复或放弃草稿
- **手机 / 平板**：长按 400 毫秒后拖动

> 界面设置（主题模式、默认搜索引擎、隐私模式）在管理面板的 **首页导航** 分区。

### 站点默认首页

管理面板 → 首页导航 → 编辑站点默认首页，可独立编辑分类、链接、搜索引擎和外观，调整顺序并预览。先点「保存草稿」，再明确点击「发布默认首页」，公开模板才会更新。管理员个人导航保持原样。默认首页只影响导航、搜索引擎与外观；模块的启用与开放是另一套（管理面板 → **模块**），不随它的发布变化。

升级时保留原完整管理员配置，并生成独立默认副本。导航、草稿和已发布模板分别存入 SQLite，旧 `config.json` 只作为首次迁移来源保留。旧页面保存会提示刷新，版本冲突也会拒绝覆盖。升级前的私有快照位于 `.navigation-upgrade-snapshot/`，按其中 `RESTORE.txt` 和 `RESTORE.json` 在停服状态下恢复全部数据，并使用升级前程序。

### 超级搜索框

搜索框是三合一的入口，按输入的第一个字符区分用途。

**搜索网页**：直接输入关键词按 `Enter`，用当前引擎搜索。点击框内的引擎名称可切换引擎，也可以在管理面板的 **首页导航** 分区添加自定义引擎。

**检索书签**：管理员登录后，点搜索框左侧的「网页」按钮切换到「书签」，或直接输入 `/` 或 `、`。输入关键词实时匹配标题、网址、分类与描述；`↑↓` 选择，`Enter` 打开，`Esc` 退出。

**分享文本**：输入 `>` 或 `》` 进入分享模式，输入内容后按 `Enter` 生成链接。可在同一界面设置 4 位 PIN 码；内容在浏览器内加密，服务器只存密文；有效期可选 5 分钟 / 30 分钟 / 1 天 / 7 天，阅后即删。在另一台设备打开链接即可查看，无需登录、无需安装应用。

### 书签集中管理

- **导入**：管理面板 → 收藏夹 → 导入书签，选择浏览器导出的书签 HTML（Netscape 格式，Chrome、Edge、Firefox、Safari、Opera、Brave 等均可导出）
- **整理**：收藏管理器提供分类树、搜索、批量设置隐私与删除；拖拽书签即可改变分类
- **导出**：管理面板 → 收藏夹 → 导出书签，导出标准 HTML 格式，可导入任何浏览器

> 收藏库及其检索、分类、计数和导出仅向管理员开放，原非私密条目同样需要登录。首页公开导航链接与匿名文本分享继续可用。

> 这里管理的是导入的书签；首页导航的分类与链接是另一份数据，见上方「自定义导航」。

### WebDAV 远程备份

把**收藏、备忘录、私人模块设置与时间线**备份到 WebDAV 服务器（坚果云、NextCloud 等）。

- **配置**：管理面板 → 账户与备份 → 远程备份，填写地址、用户名与密码，点「测试连接」验证后点「立即备份」
- **自动同步**：勾选「启用 WebDAV 备份」后，可再勾选「自动同步」。此后这些数据发生变化时会自动备份一次，同一时段的连续改动合并为一次
- **备份内容**（按时间戳归为同一组；没有对应数据时该文件不生成）：

| 文件 | 内容 |
|------|------|
| `nav-sylph-bookmarks-{时间戳}.html` | 收藏夹，浏览器兼容格式，保留隐私标签，可直接导入 Chrome/Edge |
| `nav-sylph-memos-{时间戳}.json` | 备忘录的标题、正文与置顶状态 |
| `nav-sylph-modules-{时间戳}.json` | 监控目标、私人模块的开关与布局；**不含任何凭据**（agent token、推送凭据、部署令牌都被剔除） |
| `nav-sylph-timeline-{时间戳}.json` | 时间线的来源、事件与归档 / 收藏状态；**不含社交平台凭据** |
| `nav-sylph-manifest-{时间戳}.json` | 清单：这次包含哪些域、每个文件的字节校验和，以及**这次跳过了什么、为什么** |

**不在备份范围**：管理员个人导航与搜索引擎、站点默认模板、普通口令空间与邀请码、设备令牌、管理员密码、登录会话、监控缓存。恢复后需要重新授权/重新部署的项目（例如缺凭据的监控机器）会在恢复对话框里列出来。

**恢复**是两段式：点「恢复」先**预览**——会列出「将恢复」与「将跳过」的每一项及原因、哪些机器的凭据需要重新授权、以及恢复后的版本号；确认后才真正写入。恢复期间受影响的管理配置会暂时拒绝写入（其他设备的未保存草稿会收到冲突提示，不会被写回）；失败会完整回滚，连进程中断也会在下次启动时续做或回滚。

自动同步写入固定文件名的一份：`nav-sylph-bookmarks-auto.html`、`nav-sylph-memos-auto.json`、`nav-sylph-modules-auto.json`、`nav-sylph-timeline-auto.json`、`nav-sylph-manifest-auto.json`。它每次覆盖同一份，在「管理备份」里显示为「自动同步」。它不参与按时间戳分组的手动备份的保留位；手动备份只保留最新 5 组。

> 旧版本的 `nav-sylph-config-*.json`（主题、搜索引擎、首页导航）仍能在列表里看到，但**新版不再备份它、恢复时也会跳过并提示**——管理员导航与引擎不在这份备份的范围里。

- **恢复**：点「从备份恢复」选择备份时间点，可选「同时恢复配置和书签（含模块设置与时间线）」「只恢复配置」「只恢复书签」「只恢复模块设置」或「只恢复时间线」

> 管理密码文件始终不进入备份。社交平台凭据同样不进入备份——恢复之后那些来源是「待授权」状态，重新粘贴一次 token 即可（凭据密文由管理密码派生，跨安装本就解不开）。登录会话与备忘录存放在 `nav-sylph.db`，不在这份备份范围内。

### 自定义模块

模块分两类，**在开发时就固定**：

- **私人模块**（服务器监控、备忘录、Special Line 时间线）只在管理员首页可用。在管理面板的 **模块** 分区勾选启用，配置存在服务端。
- **公开模块**（微博热搜）默认关闭。管理员在同一个分区把它**对普通访客开放**，访客就能在自己的首页设置里启用它。**未开放时访客不会加载任何模块脚本**（首页首屏不受模块数量影响）；开放且访客自行启用之后，才会加载那一个模块的脚本并请求它的数据接口。

访客的模块开关、布局与偏好只存在本机浏览器，不写进管理员的服务器配置；管理员撤回开放后，访客设备会卸下该模块并停止请求，重新开放则按原偏好恢复。

| 模块 | 分类 | 内容 |
|------|------|------|
| **服务器监控** | 私人 | 首页卡片显示各机器的在线状态与 CPU、内存、存储占用 |
| **备忘录** | 私人 | 新建 / 编辑 / 置顶 / 删除，多端自动同步 |
| **Special Line 时间线** | 私人 | 社交订阅与手动保存的文章汇成一条时间线，可归档或收藏 |
| **微博热搜** | 公开 | 首页展示微博热搜榜单，每分钟刷新；显示条数可自行设置 |

- 模块区在首页分类网格之后；宽屏两侧有空间时停靠在背板左右两侧。**时间线**启用后默认停靠在右侧空白区，位置可用编辑态拖拽把手调整——拖过之后以保存的位置为准，默认停靠不会再把它挪回去
- **更新周期**在同一分区配置，可选 10 / 15 / 30 / 60 / 300 秒（访客侧的公开模块按各自的默认周期刷新）
- 备忘录同步失败时不会清空已显示的内容：卡片转为「同步失败 + 重试」，恢复后由下一次轮询自动回到已同步

#### 服务器监控

本服务只能读到运行它自己的那台主机。要监控其它机器，需要在目标机上部署一个只读的采集程序（agent）。

**添加并部署一台机器**

1. 管理面板 → 模块 → 监控目标 → 添加服务器，填写名称与地址，并选择**本服务能否直接连到这台机器**
2. 保存后在卡片上点 **部署**，生成一条命令（含一次性令牌）
3. 在目标机终端以 `sudo` 执行这条命令。它会自动安装 agent、签发证书、注册到本服务并配置开机自启
4. 回到后台，该机器变为「已就绪」，首页卡片开始显示指标。推送模式没有可探测的端口，注册成功是唯一路径，需关掉部署面板重开一次查看

**升级 agent**：部署面板的第 2 步是升级命令，只替换 agent 程序本身，凭据与证书都不变。日常升级使用它即可：

```bash
sudo /usr/local/bin/nav-agent upgrade --server <本服务地址>
```

**两种采集方式**，在添加机器时由「本服务能否直接连到这台机器」决定：

| | 拉取（能连到目标机） | 推送（目标机主动上报） |
|------|------|------|
| 连接方向 | 本服务 → 目标机 `HTTPS /metrics` | 目标机 → 本服务 |
| 目标机端口 | 需开放（默认 4195） | 不监听任何端口 |
| 判断「离线」 | 当场连不上即离线 | 超过「更新周期 × 2 + 30 秒」未上报 |

**传输安全**：拉取模式下令牌是唯一的鉴权凭据，明文传输等于把它公开在网络上，因此强制 HTTPS，agent 缺少证书时拒绝启动。若本服务用的是自签证书，请在后台勾选「本服务的 https 证书是自签的」，命令会带上 `--server-ca`，否则目标机会报 `certificate signed by unknown authority`；改完需重启本服务才生效。

**状态显示**：后台对每台机器分开显示「在线」与「部署就绪」两个状态位（便于判断是先查网络还是先部署），首页只显示在线状态。证书被更换、端口被其它程序占用分别显示为「证书异常」「端口被占」，不合并进「离线」。

> agent 支持的平台为 Linux（amd64 / arm64 / armv7）。macOS 产物仅供开发自测，其 CPU 一栏为空值：现代 macOS 移除了累计 CPU 时间的接口，取不到时留空。

> agent token 是那台机器的**只读监控凭据**：泄露它不能让攻击者改动本服务的配置，但可以读取该机器的指标。每台机器应使用不同的令牌；需要轮换时，重新执行一次部署命令即可。

#### Special Line 时间线

把社交账号的订阅内容与你手动保存的文章，按发生时间汇成一条时间线。它是登录后才可用的模块，未登录的访客看不到任何内容。

**首页位置**：时间线**直接显示在首页右侧那一列里**（不是「摘要卡 + 点开弹窗」），形态与仿真样例一致——左侧日期轨道与贯穿节点线、右侧事件卡。

宽屏下它会**让背板让位**：三列的宽度按可用空间一起算出来（时间线 400～440、中间导航 600～936、左侧监控那一列 180～220），窗口越宽时间线越宽，**不会出现「窗口缩一点、模块反而变宽」那种跳变**。放不下时（窄窗口、手机）不强行并排——模块区改成**纵向堆叠**，每张卡拿到整行宽度，时间线自己切换成窄版（时间移到卡上方、单列、竖线贴左）。

卡片自上而下：

- **头部**：标题、最近同步时间、同步中／同步失败（带重试）、立即同步所有已启用订阅、保存文章、编辑态才出现的拖拽把手
- **头部 ↻「立即同步所有已启用的订阅」**：手动触发所有正在监控的 X / 微博来源，完成后显示成功、失败、跳过来源数与新增条数；已停止的来源跳过。若批次期间没有另选筛选，会回到「全部渠道 / 全部」；若有，则保留最后选择；两种情况都会刷新该视图的最新第一页并滚到顶部。后台来源行里的单条「立即同步」仍可手动拉取已停止的那一条，且不会重新启用。
- **筛选条**：**按渠道分组**——「全部渠道」+ 每个渠道一个按钮（X / 微博 / 稍后阅读），鼠标悬停或点击按钮展开该渠道下的具体订阅人（下拉宽度随内容收窄）；右侧固定 全部 / 收藏 / 已归档。订阅人多了不会再挤掉右边的按钮；放不下会换行
- **事件列表**：列表自身滚动，卡片高度有上限（右侧那一列不会无限长下去）。向下滚动到底会**自动加载更早的事件**（列表可用键盘聚焦，方向键 / PageDown 滚动同样会加载）
- **底部**：只有一行说明——还有更早时是「向下滚动会自动加载更早事件」，到底时是「已到最早一条 · 仅保留最近 30 天（收藏过的除外）」（不再放重复的按钮）

每条 X 动态按推特的样子显示**头像、昵称与 @账号**（两者始终同时显示），并把内容**默认译成中文**（译文来自 X 自带的翻译）。点「查看原文」可切回原文，「查看译文」切回中文；正文过长时先折成 6 行，可「展开全文 / 收起」。

**订阅后会把保留窗口铺满**：新加的 X 来源会持续往更早翻页，直到取到 30 天前为止（进度会记住，服务端每轮同步接着走）。昵称与译文是**同步时补的**，所以老事件也会被补上，不需要删掉来源重建。窗口内不足一页（30 条）时没有更早的内容可加载，底部会直接显示「已到最早一条 · 仅保留最近 30 天（收藏过的除外）」。

宽屏下默认停靠在右侧空白区，可用编辑态的拖拽把手换边或换位（拖过之后以保存的位置为准）。

**配置订阅来源**（只在后台，前台没有配置入口）

1. 管理面板 → 模块 → Special Line · 订阅来源 → 添加订阅来源
2. **X**：只填用户名（可带 `@`）即可，通过 FxEmbed 公开 JSON API 采集，**不需要任何凭据**。**微博**：填昵称并粘贴开放平台的 Access Token。
3. 选择**监控周期**（1 / 5 / 15 / 30 / 60 分钟；新来源默认 5 分钟）。周期是**逐来源**的，只影响服务端自动采集，与首页模块的刷新周期无关。
4. 保存前会先测一次连通：连不上就当场报错、**不落库**，避免留下一个永远连不上的来源
5. 每一行可单独「测试连接 / 编辑 / 立即同步 / 停止监控 / 启用监控 / 重新授权 / 删除」。**停止监控**只关掉自动采集，历史内容、归档与收藏状态都保留，仍可「立即同步」手动拉一次；手动同步不会重新启用来源。删除来源会同时删除它已同步的事件

**稍后阅读**：点工具行里的「＋」，**只填链接即可**（标题与摘要选填）。留空时由**服务端**去抓目标页的标题与摘要，抓不到就退回用链接当标题并提示你；同一链接再次保存是**更新**那一条（不新增），保留首次保存时间。

**时间线操作**：事件标题本身就是原文链接（新标签页打开）。每张事件卡只有两个动作：

- **右上角「归档 / 取消归档」**：把这条从时间线收起来——它只出现在「已归档」筛选里，「全部」与「收藏」都看不到它；点「取消归档」就回到原时间线。**归档不延长保留期**（到 30 天照样被清理）。
- **右下角五角星「收藏 / 已收藏」**：**长期保存**——不会被 30 天清理删掉，一直留在原时间线，并在「收藏」筛选里集中查看。

> 「收藏」与首页导航那个**「收藏夹」（书签）**是两回事：前者是时间线事件的标记，存在服务端时间线库里；后者是导航书签（`favorites.json`）。两者互不影响。

筛选：想看某个账号就展开它所在渠道的按钮选一下；「全部渠道」清空来源筛选。右侧的 全部 / 收藏 / 已归档 是内容状态筛选：**归档过的事件只在「已归档」里出现**（哪怕它同时被收藏）。

**凭据只存在服务端**：任何接口都不会把 token 回传给页面（连密文都不回），页面只知道「有没有配置」。X 走 FxEmbed，本来就没有凭据。因此**改管理密码时凭据会一并重新加密**，而**备份里不含凭据**——恢复之后微博来源需要重新授权一次（X 不需要）。

**数据保留**：社交订阅事件**只保留最近 30 天**，更早的由服务端定时清理；这就是列表底部那句「仅保留最近 30 天」的含义。你手动保存的文章不按时间清理，上限 500 条。触顶时会明确报错而不是静默丢弃。

**关于翻译与头像**：译文由服务端在采集时逐条向 FxEmbed 取（用的是 X 自带的翻译），随事件一起存在本地，因此**打开页面时不再额外请求**；单轮最多翻译 20 条，取不到就显示原文。头像直接引用 X 的图片地址（`pbs.twimg.com`），这是本模块唯一的外部图片请求；加载失败时会退回一个首字母方块。想完全避免外站图片，可去掉这一处渲染（见 `docs/architecture.md`）。

> **X 走 FxEmbed**（`api.fxtwitter.com`）的公开 JSON API：只要用户名公开可访问即可，**不需要开发者账号或任何凭据**。FxEmbed 是第三方服务，它对上游的抓取时效与可用性不由本项目控制；失败时来源行会显示原因，稍后重试或缩短周期即可。
>
> **微博**仍走开放平台官方接口，需要开放平台应用审核通过的 access_token。本项目的开发环境**没有**微博凭据，因此**没有对微博真实接口做过连通验证**——测试用的是固定响应的 fixture，请以界面上「测试连接」的真实结果为准。凭据过期时该来源显示「授权失效」，重新粘贴一次即可。

### 安全特性

- **管理密码** bcrypt 加密存储；管理密码至少12个字符，包含大写、小写、数字、符号中的至少三类，且不超过72字节；旧弱密码登录后只能在10分钟内改密或退出，取消改密即退出
- **登录防爆破**分三层：每 IP 限流、同一 IP 连续 10 次密码错误锁定 30 分钟、全站总量封顶。客户端区分「密码错误」「已锁定（含剩余秒数）」「总量封顶」三种提示
- **会话**：登录后签发 32 字节随机令牌，放在 `HttpOnly` Cookie 中下发；会话落盘在 SQLite，服务重启与版本升级后无需重新登录。普通会话 24 小时，勾选「信任此设备」为 30 天滑动续期
- **登录环境校验**：比对设备指纹与 IP 归属地，检测到变化时**自动登出**，并在页面底部提示重新登录
- **分享内容端到端加密**（AES-256-GCM），服务器只存密文，看不到原文
- **收藏访问控制**：全部收藏仅接受正常管理会话，私密标签保留原有管理与备份用途
- 私有数据文件（配置、书签、密码、模块配置、会话库）由服务收紧到 0600

### 其他特性

- **主题切换**：浅色 / 深色 / 跟随系统三态，未登录也可在本机切换
- **PWA**：可安装到桌面或手机主屏，离线可用。桌面浏览器点地址栏的安装图标；iOS Safari 用「分享 → 添加到主屏幕」；Android 用「菜单 → 添加到主屏幕」
- **响应式布局**：适配手机、平板与桌面端
- **版本提示**：新版本发布后，页面右下角「说明」入口会提示更新亮点

## 🚀 安装

### 一键安装

```bash
curl -fsSL https://raw.githubusercontent.com/mh567/nav-sylph/main/sylph.sh | bash
```

支持 Linux / macOS / Windows (Git Bash, WSL)。脚本会从 [GitHub Releases](https://github.com/mh567/nav-sylph/releases) 下载最新版本，无需安装 Git；国内服务器下载失败时会自动尝试镜像加速。

### 系统要求

- **Node.js** 22+（`better-sqlite3` 要求，登录会话与模块数据落盘依赖它）
- **curl** 或 **wget**
- 使用服务器监控时，被监控主机需为 **Linux**（amd64 / arm64 / armv7）。agent 是单一静态二进制，目标机无需安装任何运行时

### 首次使用

| 项目 | 值 |
|------|-----|
| 访问地址 | http://127.0.0.1:4000 |
| 管理密码 | `admin123` |

> **默认密码仅用于首次改密**，升级后旧管理会话全部失效。弱密码登录只取得10分钟且不续期的改密凭据。修改成功后撤销全部旧会话，为当前设备建立正常会话；凭据重加密失败会明确报错。

> 登录状态由服务端会话 + `HttpOnly` Cookie 维持：刷新页面、关闭标签页、以及服务重启或版本升级后都仍然有效，直到过期、主动退出、修改密码，或检测到登录环境变化。

### 管理脚本

项目使用统一的 `sylph.sh` 脚本进行所有操作：

| 命令 | 说明 |
|------|------|
| `./sylph.sh start` / `stop` / `restart` | 启动 / 停止 / 重启服务 |
| `./sylph.sh status` | 查看运行状态 |
| `./sylph.sh logs` | 查看实时日志 |
| `./sylph.sh install` | 初始化安装 |
| `./sylph.sh update` | 更新到最新版本（保留配置） |
| `./sylph.sh uninstall` | 完全卸载 |
| `sudo ./sylph.sh enable` / `disable` | 开机自启（Linux） |

### 版本更新

```bash
./sylph.sh update
```

更新时会自动：校验 Node 版本（低于 22 直接拒绝更新）→ 备份用户配置与数据库 → 从 GitHub Release 下载最新版本 → 恢复配置并重启服务 → 显示版本变化与更新亮点。

备份清单为 `config.json`、`favorites.json`、`.admin-password.json`、`.env`、`server-config.json` 与 `nav-sylph.db`，其余数据文件原地保留。登录会话在 `nav-sylph.db` 中且升级保留，因此更新后无需重新登录。

> 需要 **Node.js 22+**。低版本请先升级 Node，再执行更新——脚本会先校验并拒绝，不会改动你的文件。

若从 v1.5.0 更新时遇到「服务未运行」后又提示端口 4000 被占用、且服务由 systemd 管理，请先在安装目录获取新版管理脚本，再执行更新：

```bash
curl -fsSL https://raw.githubusercontent.com/mh567/nav-sylph/main/sylph.sh -o sylph.sh
chmod +x sylph.sh
./sylph.sh update
```

### 自定义安装目录

```bash
NAV_SYLPH_DIR=/opt/nav-sylph curl -fsSL https://raw.githubusercontent.com/mh567/nav-sylph/main/sylph.sh | bash
```

## ⚙️ 配置

### 配置文件

| 文件 | 用途 | 说明 |
|------|------|------|
| `.env` | 服务器配置 | 端口、HTTPS 等 |
| `config.json` | 主配置 | 主题、搜索引擎、首页导航分类 |
| `favorites.json` | 收藏夹数据 | 导入的浏览器书签数据 |
| `.modules.json` | 模块配置 | 监控目标、模块开关、布局与更新周期；凭据不以明文存储 |
| `.webdav-config.json` | WebDAV 配置 | 远程备份服务器配置（加密存储） |
| `version.json` | 版本信息 | 当前安装版本 |
| `.admin-password.json` | 管理密码 | 自动生成，bcrypt 加密存储 |
| `nav-sylph.db` | SQLite 库 | 登录会话、备忘录与监控指标缓存，自动生成，权限 600 |

> 除 `.env` 与 `version.json` 外，以上文件均由服务在创建/写入时收紧到 0600，并在每次启动兜底校正。版本更新只清理程序文件，数据文件均会保留。

### 环境变量

复制 `.env.example` 为 `.env` 进行配置：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `SERVER_HOST` | `127.0.0.1` | 监听地址（`0.0.0.0` 允许外部访问） |
| `SERVER_PORT` | `4000` | 监听端口 |
| `HTTPS_ENABLED` | `false` | 启用 HTTPS |
| `HTTPS_KEY_PATH` | - | SSL 私钥路径 |
| `HTTPS_CERT_PATH` | - | SSL 证书路径 |
| `HTTPS_CA_PATH` | - | 中间证书链路径（可选） |
| `ADMIN_PASSWORD_FILE` | `.admin-password.json` | 管理密码文件 |
| `COOKIE_SECURE` | `true` | 覆盖登录 Cookie 的 `Secure` 自动判断 |
| `GEO_ENABLED` | `true` | 是否用 IP 归属地辅助判断登录环境是否变化 |
| `GEO_SCOPE` | `province` | 地理比对粒度：`province` / `city` / `off` |
| `GEO_DATABASE` | `lib/geo/ip2region_v4.xdb` | 离线 IP 归属库路径 |
| `DB_FILE` | `nav-sylph.db` | SQLite 库文件路径 |
| `LOG_DIR` | `logs` | 日志目录 |

> 登录 Cookie 的 `Secure` 标记是**自动判断**的：请求经 https 到达
> （`HTTPS_ENABLED=true`，或反代回填 `X-Forwarded-Proto: https`）才加，
> 纯 http 部署自动省略——否则浏览器不会保存该 Cookie，表现为「密码正确但一直未登录」。
>
> 因此**一般无需配置 `COOKIE_SECURE`**，它只用于覆盖上述自动判断。

> `.env.example` 中另有 `DATA_FILE`、`ICON_PATH`、`FAVICON_PATH` 三项，当前版本并未读取（页面图标固定引用 `public/` 下的文件），设置后不生效，故未列入上表。
>
> `NAV_AUTO_SYNC_DELAY_MS` 控制自动同步把连续改动合并成一次上传的等待时间，默认 30000 毫秒。正常使用无需设置，它只用于把等待压短以便测试。
>
> `NAV_WEIBO_HOT_URL` 覆盖微博热搜模块的上游地址（默认 `https://api.xunjinlu.fun/api/rebang/weibo.php`）。正常使用无需设置；它给自动化测试一个本地桩（否则用例会真的连外网，也无法断言「并发只取一趟」），自建部署也可以指向自己的镜像。

## 📁 项目结构

```
nav-sylph/
├── public/          # 前端页面、样式、脚本与功能模块
├── lib/             # 后端模块（监控、会话、备份、凭据加密、SQLite）
├── agent/           # 部署在被监控主机上的 Go 采集程序
├── server-config/   # 服务配置的默认值与加载校验
├── scripts/         # agent 交叉编译与版本发布脚本
├── tests/           # 回归测试
├── server.js        # 后端服务入口
└── sylph.sh         # 安装与维护脚本
```

前端为原生 HTML / CSS / JavaScript，后端为 Node.js + Express，数据存 JSON 与 SQLite；被监控主机上的采集程序为 Go 静态二进制，零第三方依赖。

已实现的结构与设计约束见 [docs/architecture.md](docs/architecture.md)，部署细节见 [DEPLOYMENT.md](DEPLOYMENT.md)。
