# Nav Sylph

一个极简、高效的个人导航与书签管理页面。

## ✨ 核心特点

| 特点 | 说明 |
|------|------|
| **极简设计** | 紧凑纯文字导航，专注搜索与书签 |
| **书签检索** | 导入浏览器书签，通过模式按钮或 `/`、`、` 触发模糊搜索 |
| **首页导航** | 分类管理、拖拽排序、纯文字导航 |
| **首页编辑模式** | 登录后可直接在首页拖拽调整模块与书签布局，改完一次性保存 |
| **多搜索引擎** | 内置 Google、百度、Bing、DuckDuckGo，可自定义 |
| **登录后模块** | 服务器监控、备忘录仅在登录后按需加载，不影响访客首屏 |
| **服务器监控** | 在被监控主机上运行只读 agent，卡片显示在线状态、CPU、内存与存储占用 |
| **WebDAV 备份** | 备份配置、书签与模块设置，可选择性恢复 |
| **跨设备分享** | 端到端加密的临时文本分享，有效期可选，阅后即删 |
| **主题切换** | 支持浅色/深色/跟随系统三种模式 |
| **PWA 支持** | 可安装到桌面或手机主屏，离线可用 |
| **响应式布局** | 适配手机、平板和桌面端 |
| **版本提示** | 新版本发布后在说明入口提示更新亮点 |
| **安全防护** | bcrypt 密码、登录三层限流、HttpOnly 会话 Cookie、设备与归属地校验、安全响应头 |

## 🚀 快速开始

### 项目简介

Nav Sylph 是一个基于 **Node.js** 的轻量级 Web 应用，可部署在个人服务器或本地电脑上，作为浏览器首页使用。

### 一键安装

```bash
curl -fsSL https://raw.githubusercontent.com/mh567/nav-sylph/main/sylph.sh | bash
```

支持 Linux / macOS / Windows (Git Bash, WSL)

> 💡 安装脚本会自动从 [GitHub Releases](https://github.com/mh567/nav-sylph/releases) 下载最新版本，无需安装 Git。国内服务器如遇下载失败，脚本会自动尝试镜像加速。

### 系统要求

- **Node.js** 22+（`better-sqlite3` 要求，登录会话与模块数据落盘依赖它）
- **curl** 或 **wget**（用于下载）
- 使用服务器监控时，被监控主机需为 **Linux**（amd64 / arm64 / armv7）。agent 是单一静态二进制，目标机无需安装任何运行时

## 📦 管理脚本

项目使用统一的 `sylph.sh` 脚本进行所有操作：

### 基础命令

| 命令 | 说明 |
|------|------|
| `./sylph.sh start` | 启动服务 |
| `./sylph.sh stop` | 停止服务 |
| `./sylph.sh restart` | 重启服务 |
| `./sylph.sh status` | 查看运行状态 |
| `./sylph.sh logs` | 查看实时日志 |

### 安装与维护

| 命令 | 说明 |
|------|------|
| `./sylph.sh install` | 初始化安装 |
| `./sylph.sh update` | 更新到最新版本（保留配置） |
| `./sylph.sh uninstall` | 完全卸载 |

### 版本更新

```bash
# 检查并更新到最新版本
./sylph.sh update
```

更新时会自动：
- 校验 Node 版本（低于 22 会直接拒绝更新）
- 备份用户配置与数据库（`config.json`、`favorites.json`、`.admin-password.json`、`.env`、`server-config.json`、`nav-sylph.db`）
- 从 GitHub Release 下载最新版本
- 恢复配置并重启服务
- 显示版本变化和更新亮点

> 需要 **Node.js 22+**。低版本请先升级 Node，再执行更新——`./sylph.sh update` 会先校验并拒绝，不会改动你的文件。

> 登录会话存放在 `nav-sylph.db` 中且升级时保留，因此更新后无需重新登录。

> 💡 更新后可点击页面右下角“说明”查看新功能；有新版本时入口会显示提示。

若从 v1.5.0 更新时遇到“服务未运行”后又提示端口 4000 被占用，且服务由 systemd 管理，请先在安装目录获取新版管理脚本，再执行更新：

```bash
curl -fsSL https://raw.githubusercontent.com/mh567/nav-sylph/main/sylph.sh -o sylph.sh
chmod +x sylph.sh
./sylph.sh update
```

新版脚本会通过 systemd 停止并启动当前安装目录的服务。若安装目录需要管理员写入权限，下载到临时文件后再由管理员复制到安装目录。

### 开机自启

| 系统 | 命令 |

## ⚙️ 系统配置

### 配置文件

| 文件 | 用途 | 说明 |
|------|------|------|
| `.env` | 服务器配置 | 端口、HTTPS 等 |
| `config.json` | 主配置 | 主题、搜索引擎、首页导航分类 |
| `favorites.json` | 收藏夹数据 | 导入的浏览器书签数据 |
| `.modules.json` | 模块配置 | 监控目标、模块开关、布局与更新周期；凭据不以明文存储 |
| `.webdav-config.json` | WebDAV 配置 | 远程备份服务器配置（加密存储） |
| `version.json` | 版本信息 | 当前安装版本 |
| `.admin-password.json` | 管理密码 | 自动生成，bcrypt 加密存储 |
| `nav-sylph.db` | SQLite 库 | 登录会话、备忘录与监控指标缓存，自动生成，权限 600 |

> 除 `.env` 与 `version.json` 外，以上文件均由服务在创建/写入时收紧到 0600，并在每次启动兜底校正。

> 版本更新只清理程序文件，数据文件均会保留（见上方「版本更新」的备份清单），因此升级不会丢失书签、密码或模块配置。

### 配置优先级

```
默认值 → server-config.json → .env → 环境变量
```

### 环境变量

复制 `.env.example` 为 `.env` 进行配置：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `SERVER_HOST` | `127.0.0.1` | 监听地址（`0.0.0.0` 允许外部访问） |
| `SERVER_PORT` | `4000` | 监听端口 |
| `HTTPS_ENABLED` | `false` | 启用 HTTPS |
| `HTTPS_KEY_PATH` | - | SSL 私钥路径 |
| `HTTPS_CERT_PATH` | - | SSL 证书路径 |
| `HTTPS_CA_PATH` | - | 中间证书链路径（可选） |
| `ADMIN_PASSWORD_FILE` | `.admin-password.json` | 管理密码文件 |
| `COOKIE_SECURE` | `true` | 覆盖登录 Cookie 的 `Secure` 自动判断 |
| `GEO_ENABLED` | `true` | 是否用 IP 归属地辅助判断登录环境是否变化 |
| `GEO_SCOPE` | `province` | 地理比对粒度：`province` / `city` / `off` |
| `GEO_DATABASE` | `lib/geo/ip2region_v4.xdb` | 离线 IP 归属库路径 |
| `DB_FILE` | `nav-sylph.db` | SQLite 库文件路径 |
| `LOG_DIR` | `logs` | 日志目录 |

> 登录 Cookie 的 `Secure` 标记是**自动判断**的：请求经 https 到达
> （`HTTPS_ENABLED=true`，或反代回填 `X-Forwarded-Proto: https`）才加，
> 纯 http 部署自动省略——否则浏览器不会保存该 Cookie，表现为「密码正确但一直未登录」。
>
> 因此**一般无需配置 `COOKIE_SECURE`**，它只用于覆盖上述自动判断。

> `.env.example` 中另有 `DATA_FILE`、`ICON_PATH`、`FAVICON_PATH` 三项，当前版本并未读取（页面图标固定引用 `public/` 下的文件），设置后不生效，故未列入上表。

## 🖥️ 使用说明

### 默认账户

| 项目 | 值 |
|------|-----|
| 访问地址 | http://127.0.0.1:4000 |
| 管理密码 | `admin123` |

> **使用默认密码登录时会提示立即修改**，修改需要输入当前密码；修改成功后全部会话失效，需要重新登录。

> 登录状态由服务端会话 + `HttpOnly` Cookie 维持：刷新页面、关闭标签页、以及服务重启或版本升级后都仍然有效，直到过期、主动退出、修改密码，或检测到登录环境变化。普通会话默认 24 小时，勾选「信任此设备」后为 30 天滑动续期。

> 检测到登录环境变化（设备指纹不匹配，或归属地变化）时会**自动登出**，并在页面底部弹出一条提示，提示重新登录。

### 管理面板

点击页面右下角的 **管理** 按钮进入管理面板。面板分为四个分区，宽屏为左侧侧栏，窄屏为顶部横向标签条：

| 分区 | 内容 |
|------|------|
| **首页导航** | 主题模式、默认搜索引擎、隐私模式、搜索引擎编辑器 |
| **收藏夹** | 导入 / 导出 / 添加书签，以及收藏管理器（分类树、搜索、批量隐私与删除） |
| **模块** | 模块开关、监控目标（添加 / 编辑服务器、生成部署与升级命令）、本服务自签证书、更新周期 |
| **账户与备份** | 登录安全（信任此设备）、远程备份、退出登录 |

> 两份书签数据注意区分：**首页导航**是首页网格里的分类与链接（在首页编辑模式中编辑），**收藏夹**是导入并保存在 `favorites.json` 的书签。两者的分类结构相似，但不是同一份数据。

### 首页编辑模式

点击页面右下角的 **编辑** 按钮（登录后可见）进入首页编辑模式：

- **模块区**：拖拽调整卡片顺序；宽屏下还可拖到左右两侧
- **书签**：在分类之间、分类内部拖拽排序；卡上的 ✕ 删除该书签，点击卡片可修改标题与 URL
- **分类头**：⠿ 拖拽，✎ 重命名，✕ 删除
- **新增**：每个分类末尾有「＋」卡新增该书签，网格末尾有「＋ 添加分类」
- **保存**：编辑期间的改动只保留在本地，点右下角「保存编辑」一次性提交；按 `Esc` 或自动登出则整体丢弃（有改动时会先确认）

> 手机与平板上为长按 400 毫秒后拖动，与桌面端的按下即拖互不冲突。

### 登录后模块

部分功能以模块形式提供，**仅在登录后加载**：未登录访客不下载任何模块脚本，首页首屏重量与模块数量无关。

在管理面板的 **模块** 分区勾选启用。当前提供：

| 模块 | 说明 |
|------|------|
| **服务器监控** | 首页卡片显示各机器的在线状态与 CPU、内存、存储占用 |
| **备忘录** | 新建 / 编辑 / 置顶 / 删除，多端自动同步 |

模块区在首页分类网格之后；宽屏两侧有空间时改为停靠在背板左右两侧。**更新周期**在同一个分区里配置，可选 10 / 15 / 30 / 60 / 300 秒。

> 备忘录的同步失败不会清空已显示的内容：卡片会转为「同步失败 + 重试」，恢复后由下一次轮询自动回到已同步。

### 服务器监控与 agent

本服务只能读到运行它自己的那台主机。要监控其它机器，需要在目标机上部署一个只读的 agent。

**添加并部署一台机器：**

1. 管理面板 → **模块** → **监控目标** → 添加服务器，填写名称与地址，并选择**本服务能否直接连到这台机器**
2. 保存后，在卡片上点击 **部署**，生成一条命令（含一次性令牌）
3. 在目标机终端以 `sudo` 执行这条命令。它会自动安装 agent、签发证书、注册到本服务，并配置开机自启
4. 回到后台，该机器会自动变为「已就绪」，首页卡片开始显示指标（推送模式没有可探测的端口，注册成功是唯一路径，需关掉面板重开一次查看）

**升级 agent：** 部署面板的第 2 步是升级命令。它只替换 agent 程序本身，凭据与证书都不变：

```bash
sudo /usr/local/bin/nav-agent upgrade --server <本服务地址>
```

> 部署与升级是两条并列的路，用途不同：**部署**会重新注册（更换令牌、重签证书），**升级**只替换二进制。日常升级使用升级命令即可。

**两种采集方式**，在添加机器时由「本服务能否直接连到这台机器」决定：

| | 拉取（能连到目标机） | 推送（目标机主动上报） |
|------|------|------|
| 连接方向 | 本服务 → 目标机 `HTTPS /metrics` | 目标机 → 本服务 |
| 目标机端口 | 需开放（默认 4195） | 不监听任何端口 |
| 判断「离线」 | 当场连不上即离线 | 超过「更新周期 × 2 + 30 秒」未上报 |

**传输安全**：拉取模式强制 HTTPS（令牌是唯一的鉴权凭据，明文传输等于把它公开在网络上），agent 缺少证书时拒绝启动。若本服务用的是自签证书，请在后台勾选「本服务的 https 证书是自签的」，命令会带上 `--server-ca`，否则目标机会报 `certificate signed by unknown authority`；改完需重启本服务才生效。

**首页与后台的状态措辞不同**：后台对每台机器分开显示「在线」与「部署就绪」两个状态位（便于判断是先查网络还是先部署），首页只显示在线状态。证书被更换、端口被其它程序占用分别显示为「证书异常」「端口被占」，不合并进「离线」。

> agent 支持的平台为 Linux（amd64 / arm64 / armv7）。macOS 产物仅供开发自测，其 CPU 一栏为空值——拿不到累计 CPU 时间时如实留空，不编造数字。

> agent token 是那台机器的**只读监控凭据**：泄露它不能让攻击者改动本服务的配置，但可以读取该机器的指标。每台机器应使用不同的令牌；需要轮换时，重新执行一次部署命令即可。

### 跨设备文本分享

快速在不同设备间传递文本，无需登录、无需安装应用。

**发送文本：**
1. 在搜索框输入 `>` 或 `》` 进入分享模式
2. 输入要分享的内容，按 `Enter` 发送
3. 可选择设置 4 位 PIN 码保护
4. 复制生成的链接

**接收文本：**
- 在另一设备打开分享链接即可查看内容

**安全特性：**
- 🔐 端到端加密（AES-256-GCM），服务器无法查看原文
- ⏱️ 有效期可选：5 分钟 / 30 分钟 / 1 天 / 7 天
- 🗑️ 阅后即删，不持久存储
- 🔒 可选 PIN 码保护

### WebDAV 远程备份

支持将配置、书签与模块设置备份到 WebDAV 服务器（如坚果云、NextCloud 等）。

**配置备份：**
1. 进入管理面板 → 账户与备份 → 远程备份
2. 填写 WebDAV 服务器地址、用户名、密码
3. 点击「测试连接」验证配置
4. 点击「立即备份」创建备份

**备份内容**（按时间戳归为同一组；书签与模块文件只在对应数据存在时生成）：

| 文件 | 内容 |
|------|------|
| `nav-sylph-config-{时间戳}.json` | 主题、搜索引擎、首页导航分类 |
| `nav-sylph-bookmarks-{时间戳}.html` | 浏览器兼容格式，保留 Sylph 书签的隐私标签，可直接导入 Chrome/Edge |
| `nav-sylph-modules-{时间戳}.json` | 监控目标、模块开关与布局；凭据不以明文存储 |

**恢复备份：**
- 点击「从备份恢复」选择备份时间点
- 可选择「同时恢复配置和书签（含模块设置）」、「只恢复配置」、「只恢复书签」或「只恢复模块设置」

> 管理密码文件始终不进入备份。登录会话与备忘录存放在 `nav-sylph.db`，不在这份备份范围内。

旧版 HTML 备份没有保存隐私标签。如原设备仍保有完整书签，请先在原设备更新应用并重新执行「立即备份」，再到新设备恢复最新备份。

## 🛠️ 技术栈

| 层级 | 技术 |
|------|------|
| **前端** | HTML5 + CSS3 + 原生 JavaScript (ES6+) |
| **后端** | Node.js + Express.js |
| **被监控主机** | Go 静态二进制（agent，零第三方依赖） |
| **存储** | JSON（配置/书签/模块设置） + SQLite（登录会话、备忘录、监控指标缓存） |
| **安全** | bcrypt、登录三层限流、HttpOnly 会话 Cookie、设备指纹与归属地校验、安全响应头、XSS 防护 |
| **PWA** | Service Worker + Web App Manifest |
