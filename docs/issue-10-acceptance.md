## 逐条验收

### 1. 无固定设备数上限；令牌 90 天不活跃失效、成功鉴权续期、每日及签发前清理，撤销使签发回执失效

- 「无上限」与 90 天失效是 #7 就有的（`DEVICE_IDLE_MS` + 鉴权时判定 + 滑动续期）；本轮补的是**清理**与**撤销的时间戳**：
  - `sync_devices.revoked_at`（迁移 v11）——清理已撤销行需要它。⚠️ 不能拿 `last_seen_at` 代替：撤销之后客户端不会再打这个令牌，它的 `last_seen_at` 停在被撤销**之前**，用它当窗口判据会把「刚撤销、客户端还没读完 401」的行当场删掉，客户端下一次请求就从 `device_revoked` 变成 `device_invalid`，话术跟着变。
  - `sweep()` 顺序固定：**已撤销行（保留 24 小时）→ 过期行（90 天）→ 墓碑（90 天，且 `id NOT IN (SELECT space_id FROM sync_devices)`）**。墓碑必须排在设备行清理之后：墓碑先没而设备行还在，客户端就从 410 变成 401，丢掉「空间已删」与「令牌无效」的区分。
  - 清理周期是 60 秒一次（比「每日」更勤），签发前另有 `pruneReceipts` ✓。
- 证据：`tests/sync-store.test.js`「清理顺序：已撤销设备行保留 24 小时；墓碑**必须在设备行清掉之后**才清」（含把顺序换过来的变异）；`tests/sync-http.test.js`「设备数量没有固定上限（连 25 台各拿一枚可用令牌）」。

### 2. 正确口令加确认可原子撤销全部旧设备并签发当前令牌，不改内容 revision、不删配置、不耗邀请；稳定请求 ID 防止重试反复撤销

- 实现：`store.resetDevices({ proof, operationId })`，单事务、顺序不可换：查空间 → `requireNotPaused` → 回执重放（`scope='reset:'+id`，同 ID 只撤一次）→ `generation+1`（**不动** revision/内容/updated_at）→ 清 `connect:`/`reset:` 回执 → **先吊销全部、后签发新设备**（反了会让新令牌当场失效）→ 写回执。
- 客户端：`confirm_reset` 态要求**重新输入口令**，`syncResetOperationId` **只放内存**（刷新后重来一次会再撤一次、多一枚 90 天内清理的孤儿令牌——这个代价写在代码注释里）；成功后走 `finishSyncConnection(..., 'reset')`（方向 `reset` ⇒ 不写 `recovery`，因为本机与云端内容都没被替换），随后 `syncPullCheck()` **先协调版本**：内容不同就摆两份候选，不静默覆盖。
- 证据：`tests/sync-store.test.js`「撤销全部旧设备：revision 与内容都不动、不消耗邀请码、同 operationId 只撤一次、旧令牌与旧回执一律作废」；`tests/sync-http.test.js`「治理路由只认管理员会话…」+ 前端接线守卫（`sync-client.test.js` 的「#10 的对话框与面板接线」）。
- 变异：先签发后吊销、不递增代次两条都红。

### 3. 授权代次约束签发回执，旧设备不能后台自动恢复；至少 20 个设备连接验证无数量限制

- 回执与代次绑定是 #7 已有的（`replayIssuance` 的三道门）；本轮「撤销全部旧设备」正是靠它让旧回执失效。
- 旧设备不自动恢复：#9 已保证没有任何路径自动调 `create`；本轮的 503 路径还额外禁止「借拒绝创建触发错误重建」（创建的 catch 里对 503 **不回查、不重发**，只转述服务端原话）。
- 20 台：`sync-http.test.js` 连 25 台，逐台可读；没有数量上限。

### 4. 每空间 1 MiB、2,000 链接、100 分类、50 引擎；全实例 1,000 空间、有效配置 1 GiB，额度并发检查，保留读取删除及缩减写入

- 结构上限（2000/100/50）是 #7 的 schema 校验（400）；**资源额度**是本轮新增（503）：
  - `sync_spaces.content_bytes` 是**物化**的 UTF-8 字节数（`config_json + modules_json` 之和），与内容在**同一条** INSERT/UPDATE 维护；
  - ⚠️ 回填必须 `LENGTH(CAST(... AS BLOB))`——SQLite 的 `LENGTH()` 对 TEXT 是**字符数**，中文配置会被算小一半以上（用例含非 ASCII 逐字对比 `Buffer.byteLength`）；
  - 额度在 writes 的单事务里检查（先查后写在并发下会超卖）：`bytes > content_bytes` 才查额度 ⇒ **缩减写入无条件放行**；超限 503 `space_quota_exceeded` / `storage_limit`，空间数超限 503 `space_limit`（**不淘汰**：淘汰会静默删掉别人还有效的配置）；
  - 读取与删除不受额度影响。
- 证据：`tests/sync-store.test.js` 的四条「额度：…」（默认值与规格逐字相等、空间数上限且不消耗邀请码、口径与 BLOB 回填、缩减放行、回执重放排在额度之前）；`tests/sync-http.test.js`「限额由环境变量注入且真的生效」。
- 测试后门：`NAV_SYNC_SPACE_LIMIT` / `NAV_SYNC_CONTENT_BYTES_LIMIT` / `NAV_SYNC_TOTAL_BYTES_LIMIT`（照既有 `NAV_AUTO_SYNC_DELAY_MS` 的手法），**另有一条断言默认值与规格逐字相等**，防止后门静默改掉已发布行为。

### 5. 上传 120/分钟、读取 240/分钟共享空间额度；连接每 IP 30/分钟、鉴权后空间签发 30/分钟，429 带 Retry-After

- #7 已实现且已验；本轮 **没有新增限流桶**（`reset` 复用连接桶 + 签发桶），所以清理定时器不用动。`tests/sync-http.test.js`「读写桶按**空间**计数，一个空间打满不影响另一个」「429 带 Retry-After，且口令猜测受每 IP 桶约束」。

### 6. 管理员仅查看非敏感内部标识、大小时间状态，可禁用删除、暂停创建及总同步；客户端区分停用、删除、过期、撤销和总暂停

- 管理员：`GET /api/admin/sync-spaces` 只回 `{ id, revision, generation, contentBytes, activeDevices, createdAt, updatedAt, disabled, disabledAt, deleted, deletedAt }` + `usage` + `settings`（**一次请求拿全**，见「自查发现」③）；`POST …/:id/disable`；`POST …/:id/delete`（**墓碑**，复用用户删除的同一个内部函数）；`POST /api/admin/sync-settings`（两个总开关，落 `sync_settings` 单行表——只放内存会在重启后静默失效）。
- 客户端：`syncTerminalOf` 的 `halt` 是**原因字符串** `'disabled' | 'paused'`（two 种暂停给两句不同的话）；总暂停时轮询换成 **5 分钟**（与服务端 503 的 `Retry-After` 同值）而不是停表，读成功即解除；停用/暂停各有自己的对话框状态（明说「重新输入口令没有用」+「重试同步」）。**没有新增第七个状态词**（设计文档 §5 的六词定死）。
- 证据：`tests/sync-http.test.js`「空间列表只回非敏感项——正文/口令哈希/令牌/回执一个字都不出现」「停用某空间 → 设备读到 403 且**连接保留**；重新启用后同一个令牌立刻可用」「管理员删除 → 410，与「设备被踢」「令牌无效」三种回答可分辨」「总暂停——读/写/连/建/重签一律 503 且带 Retry-After；删除与撤销照常可用」「暂停新建只挡创建（已有空间照常同步），且被拒的创建不烧掉邀请码」；引擎「总暂停：保留连接、换成 5 分钟慢轮询…」。
- 真实浏览器（`tests/browser/sync-governance.cjs`，6 条，连跑三次 6/6）：总开关勾了即落盘且刷新后仍生效、列表不泄露正文与长串、暂停新建的提示且只发一次创建请求、总暂停→暂停态→解除后恢复、停用→重新启用后手动重试恢复、管理员删除→访客「已被删除」+ 导航保留 + 不重建、写满被拒时内容不丢且不退避、精简后同步成功。

### 7. 验证空间总量、体积边界、重复连接回收及限流，不借拒绝创建触发错误重建

- 空间总量与体积边界：注入小限额后真实 HTTP 打边界（见 §4 的证据）；重复连接回收是 #7 的「同 operationId 不新增设备行」；限流见 §5。
- 「不借拒绝创建触发错误重建」：创建路径的 catch 对 503 **不回查 `check`、不重发**（用例断言只发一次创建请求、界面停在原状态）；额度类 503 在上传路径**不排退避、不丢 pending、不清连接**（引擎用例 + 浏览器用例）。

## 本轮自查发现并修掉的三个缺陷（都由验证抓到，未进入任何发布版本）

1. **后台两个总开关没有回填**：`renderSyncSpaces()` 把设置读进内存，但只重画了列表——`paintSyncPolicy()` 在面板渲染那一刻跑（此时设置还没到）就直接返回，于是「上次开过总暂停，这次打开面板却看着是关的」。修法：拉到设置之后先 `paintSyncPolicy()` 再画列表。浏览器用例第一条抓到的。
2. **删除空间用的是原生 `window.confirm`**：它阻塞脚本线程、样式与项目其它危险确认不一致，自动化里还会被默认丢掉（等于按钮永远点不成）。改成仓库自己的 `confirmAction(..., danger)`；守卫也从「钉 `window.confirm(` 这个实现」改成钉「删除前必须确认」这个**意图**。
3. **面板每打开一次多打两条管理接口** → 撞管理桶（30 次/分钟）：既有的 `tests/browser/admin-sync.cjs` 两条用例稳定变红（`#pollIntervalSelect` 出不来 = 那条 GET 被 429 了）。按计划把列表与策略合并成**一条** GET（服务端 `listSpaces()` 的响应带 `settings`），并加了一条「面板重画只允许一条 GET」的守卫。这正是本仓库踩过的「渲染函数里顺手预取」那个坑。
