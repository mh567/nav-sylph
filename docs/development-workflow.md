# 开发与交付流程

适用范围：本仓库的 Issue 开发、续做、验收和收尾。开始时从远端和实际仓库核对状态，交接记录用于定位证据。单次对话结束或切换 Agent 不会自动取消尚未完成的交付步骤。

## 交付范围与授权

- 用户指派一个 Issue 的完整开发时，将实现、验证、审查、交接和该 Issue 收尾一起列入待办。提交、推送、远端验收清单及评论更新、关闭 Issue、版本发布分别核对用户的实际授权；已有授权无需重复询问。
- 获得“完成所有流程”等完整交付授权后，连续完成已满足条件的提交、推送和 Issue 收尾，直到读取远端确认。发布新版本需要明确发布授权，Issue 关闭与版本发布分别执行。
- 仅获部分授权时，先完成可执行的工作并准备好完整交付文本；明确指出剩余步骤及所缺授权。仅获“推送”授权时，还要检查此前的 Issue 收尾授权，避免遗漏已经可以执行的步骤。
- 需求不清、验收失败、必要环境不可用或缺少授权时，记录具体缺口及恢复入口。未满足的验收项保持未勾选，Issue 保持打开；结束回复使用实际阶段，避免笼统宣称全部完成。

## 执行顺序与完成条件

| 阶段 | 必须执行 | 完成条件 |
| --- | --- | --- |
| 1. 接单与基线 | 阅读 README、架构、交接、Issue 正文、评论和父规格；检查依赖、分支、HEAD、工作区和相关代码 | 记录 Issue、起始 SHA、范围、逐条验收要求及已有未提交改动；依赖满足或范围已明确 |
| 2. 测试边界 | 按规格确定实际公共接口、持久化与浏览器入口；确认配置、升级和兼容影响 | 每个验收项都有计划验证入口；采用 tdd 技能时遵守其测试边界确认要求 |
| 3. 实现与定向验证 | 最小完整修改，覆盖调用方、配置及受影响夹具；适合时先复现失败再修复，每个切片运行定向测试 | 定向行为通过；权限、数据迁移和真实持久化执行实际实现；避免以源码字符串或 mock 仓储代替验收 |
| 4. 候选检查 | 按 AGENTS.md 运行全量测试、适用语法检查和差异检查；完成规格要求的真实浏览器或目标环境验证 | 逐条记录命令、结果和实际验证环境；测试失败已修复或有明确未完成项，不能只报定向成功 |
| 5. 审查与整改 | 分别审查 Standards 和 Spec；使用 code-review 技能时按其规定执行两轴审查；固定起始 SHA 和待审差异 | 阻塞问题均已修复并复审；代码变化后重跑受影响检查，按新增风险决定是否重跑全量 |
| 6. 本地提交 | 更新交接，稳定结构变化更新架构；只暂存本任务改动，检查 staged diff；在 main 提交并关联 Issue | 记录实际提交 SHA，提交内容不混入用户已有修改；提交后核对工作区剩余内容 |
| 7. 推送与确认 | 获得授权后核对待推送提交及远端状态，推送 main；远端领先时先理解差异，保留双方改动并按范围验证 | 成功读取远端 main，确认包含交付提交；本地提交成功不能代替推送成功，不用强推覆盖远端 |
| 8. Issue 验收收尾 | 对照最终提交逐项核验证据，勾选满足的条件，发布完成说明；全部条件满足且有授权后以 completed 关闭 | 重新读取 Issue，核对验收清单、评论内容及链接、CLOSED 状态和关闭原因；缺一项就记录待办 |
| 9. 交接与回复 | 同步实际提交、推送、Issue 状态和后续工作；必要的收尾文档单独提交推送 | 最终回复中的提交号与远端一致，Issue 链接可用，未验证事项清晰，原有未提交内容仍保留 |

单 main 开发沿用仓库约定，完整交付不强制创建 PR。若用户指定 PR，则另行完成其审查、CI 和合并要求，仍核对关联 Issue 的最终状态。

## 证据与关闭规则

每个验收项记录：要求、对应实现、验证入口与结果、限制。把实现存在、定向测试、全量测试、CI、审查、真实浏览器、目标服务器及发布附件分开陈述。只有实际观察到的结果才写“通过”；先前结果须关联对应 SHA，代码变化后检查证据是否仍适用。

- 必验环境或行为尚未验证时，验收项保持未勾选。明确属于后续任务的综合验收可以单列，引用其归属，当前 Issue 只能按自身范围关闭。
- 修复已有失败后保留真实回归测试；需求改变导致旧测试失效时更新其预期或入口，并说明替代证据。避免为了全绿削弱权限或删除仍有效的行为验证。
- 推送、提及 `(#编号)`、关闭 Issue 和发布 Release 是不同操作。提交中的 Issue 引用不会自动关闭 Issue；即使使用关闭关键词，也要读取远端确认最终状态。
- 无法发布评论或关闭 Issue 时，保留已准备的文本和具体失败信息，回复明确写出“已推送，Issue 待收尾”，避免宣称整个交付完成。
- 子任务完成只关闭对应子 Issue。父 Issue 的全部条件与最终综合验收尚未满足时，继续保持打开。

## Issue 完成说明模板

先准备完整文本，再按授权发布。内容只保留本次相关项目，结果用实际证据替换。

```markdown
实现提交：[SHA](提交链接)，已推送 main。

## 验收证据

1. 对应第一条验收要求：实现位置、验证入口、结果。
2. 依次覆盖其余验收要求；未完成项及原因单列。

## Standards

审查结论、发现的问题及整改复审结果。

## Spec

逐条需求符合性、缺项及范围变化。

## Verification and limits

- 定向、全量、语法及差异检查：实际命令与结果。
- 浏览器或目标环境：实际验证范围。
- 未验证事项、后续任务归属，以及当前发布状态。
```

## 最终收尾检查

结束前逐项确认；不适用项注明理由，不能默认为已完成。

- [ ] 每条验收要求均有对应证据，缺项仍明确列出。
- [ ] 必要测试及两轴审查完成，阻塞发现已修复复审。
- [ ] 本任务提交已形成，用户已有未提交改动保持原状。
- [ ] 已授权的推送完成，远端 main 包含交付提交。
- [ ] 已授权的 Issue 清单与完成说明已发布并读取核对。
- [ ] 全部验收满足时，已授权的 Issue 关闭完成且远端状态已确认。
- [ ] 交接记录与最终回复对应实际远端状态。
- [ ] 发布状态单独说明；有发布授权时按 AGENTS.md 和 scripts/release.sh 完成并验证 Release 与附件。
